# 定价算法逆向工程 — 研究纪要（2026-10-10）

> 用户问题：「这个市场价格高度准确，是因为背后有程序在计算……现在就是要找到定价的算法，你有什么好的想法吗？」
>
> 本文记录已经**实证确认**的部分、以及**下一步该往哪里挖**的路线图。

---

## 一、已确认：结算规则（官方原文，非推测）

来源：`gamma-api.polymarket.com/markets/slug/btc-updown-5m-<ts>` 的 `description` 字段。

> "This market will resolve to **"Up"** if the **time-weighted average price (TWAP) of Bitcoin, generated by Chainlink**, of the time range specified in the title is greater than or equal to the price at the beginning of that range. Otherwise, it will resolve to **"Down"**.
> The resolution source … is the **BTC/USD TWAP data stream** available at
> `https://data.chain.link/streams/btc-usd-twap-60s-streams`.
> …not according to any other sources or spot markets."

**要点**：
- 结算参考 = **Chainlink 的 BTC/USD TWAP（60 秒流）**，**不是** Binance/Coinbase 现货，**不是**最终成交流；
- 判定 = 「窗口内的 TWAP」与「窗口起始价」比较；
- 这意味着结算值**被平滑过**（含 60s 均值），比"终点价"更难被最后一秒的跳动翻转。

---

## 二、已确认：定价核形态 = 数字期权公式

对 44.9 天、1,039,610 条快照（12,024 个窗口）做反解：

定义 `U(τ) := (m / 1e4) / z`，其中 `m` = 朝热门腿方向的位移（bps），`z = Φ⁻¹(p)`，`p` = 热门腿中间价。

| τ 区间（剩余秒） | n | U 中位数（bps） | 若为 σ√τ 反推的 σ（bps/√s） |
|---|---|---|---|
| 5–15 | 10,388 | 1.28 | 0.434 |
| 15–30 | 23,562 | 1.73 | 0.375 |
| 30–60 | 67,259 | 2.33 | 0.357 |
| 60–90 | 84,978 | 3.14 | 0.366 |
| 90–120 | 93,297 | 3.77 | 0.370 |
| 120–180 | 192,776 | 4.63 | 0.382 |
| 180–240 | 180,252 | 5.49 | 0.381 |
| 240–300 | 128,064 | 5.47 | 0.334 |

**log-log 斜率 = 0.458 ≈ 0.5** → 市场按 **σ√τ（终值型数字期权）** 定价，而不是按"均价型"（那会是 ~1.0）。

**定价算法（一阶）：**
```
p(热门腿) ≈ Φ( m_bps / (σ_eff · √τ) )        σ_eff ≈ 0.37 bps/√s
```
实测底层波动率中位数 **0.317 bps/√s** → 市场隐含波动率 ≈ **1.17 × 实测**（典型的波动率风险溢价）。

## 三、已确认：市场按"现货距离"定价，而非"均价距离"

把 `z = Φ⁻¹(p_up)` 对两个候选变量回归（都以 /√τ 归一）：

| 变量 | R² | 权重 |
|---|---|---|
| `m` = (现货 − 开盘)/开盘 × 1e4（**现货距离**） | **0.594** | **92.6%** |
| `E` = [(t/300)·全窗口均价 + (τ/300)·现货 − 开盘]/开盘 × 1e4 | 0.468 | 7.4% |

联合回归：`z = 1.57·(m/√τ) − 0.13·(E/√τ)`，R² = 0.594。

→ **市场几乎完全按"当前现货 vs 开盘价"定价，几乎不考虑"窗口内均价已锁定多少"。**

## 四、已确认：用哪种结算值最能复现真实结果

用 5 种候选结算规则去预测 8,097 个窗口的实际结果：

| 规则 | 复现率 |
|---|---|
| **S1 收盘现货 > 开盘价** | **87.80%** |
| S4 末 60s 均价 > 开盘价 | 84.45% |
| S3 末 60s 均价 > 首 60s 均价 | 79.97% |
| S5 5min 均价 > 首 60s 均价 | 73.46% |
| S2 5min 均价 > 开盘价 | 73.34% |

两两分歧集上 S1 碾压其余（例：S1 vs S2 分歧 1,897 窗口，正确率 80.9% vs 19.1%）。

**注意**：S1 只有 87.8% 而非 ~100%，说明**我们记录的现货（CEX）与真实结算源（Chainlink TWAP）之间存在实质性差异**——这正是第五节的核心问题。

`P(热门腿赢 | m, τ)` 的经验胜率 vs 市场报价（每格 = 实际% / 报价%）：

| m (bps) | τ 5–30s | τ 30–60s | τ 60–120s | τ 120–300s |
|---|---|---|---|---|
| 0–2 | 89.5 / 87.5 | 82.2 / 81.4 | 74.8 / 74.3 | 66.2 / 65.8 |
| 2–5 | 96.1 / 94.2 | 91.7 / 90.5 | 85.8 / 84.6 | 74.2 / 73.6 |
| 5–10 | 95.1 / 95.9 | 94.2 / 95.0 | 91.6 / 92.1 | 82.0 / 82.1 |
| 10–20 | 99.0 / 97.2 | 97.5 / 97.3 | 95.6 / 95.1 | 88.3 / 88.7 |
| 20–40 | 85.5 / 97.0 | 97.5 / 98.7 | 98.0 / 97.0 | 92.6 / 92.9 |

绝大多数格子误差在 ±1~2pp 内。**算法本身没有可薅的空间——它有空间的地方只能是"输入"**。

## 六、结论：edge 不在公式里，只在"输入误差"里

既然价格 ≈ 一个已知公式，那么任何系统性的盈利机会只能来自下列三种"输入错误"之一：

1. **波动率输入错**（σ_eff 是慢变量，而真实波动会突变）；
2. **距离变量错**（市场用现货，结算用 TWAP——两者背离时市场就错了）；
3. **参考基准错**（结算用 Chainlink，交易者/做市商可能盯着别的源）。

### 研究路线图（按优先级）

**① 数据源校准（最高优先，且是前置条件）**
所有 44.9 天历史研究用的都是 **CEX 现货**（`btc_source=api.binance.com`），而结算是 **Chainlink TWAP-60s**。我们已实测两者存在 **约 −9bps 的系统性偏移 + 平滑差异**——这个量级**与我们要找的 edge（±1~2pp）同阶**。
→ 行动：让采集器**同时记录 Chainlink TWAP-60s 流**（`wss://ws-live-data.polymarket.com` 的 `crypto_prices_chainlink` 频道，运行器已能订阅），重跑第二节/第三节/第五节的统计。
→ **这可能证明 `[0.95,0.96]` 口袋是真的，也可能证明它只是数据源错配的产物。这是当前最大的未知数。**

**② σ 失配（波动率套利）**
实时估计市场隐含 σ（反解每次报价），与近期已实现波动率对比。判定标准：找 `σ_implied/σ_realized` 的标准差与自相关；若该比值有可预测的均值回复，则存在"市场用旧 σ 定价"的窗口。
→ 这解释了为什么"低波动夜"我们一个信号都抓不到：低波动下 σ√τ 很小，位移到 10bps 时价格早已打满。

**③ TWAP 基差（用"预期结算值"替代现货）**
既然结算含平均，构造 `预期结算值 = (t/300)·已锁定均价 + (τ/300)·现货`，用它算距离，找与现货距离背离、且市场明显只盯现货的时刻。
→ 本文第三节已经证明市场**确实只盯现货**（权重 92.6% vs 7.4%），所以只要"均价"部分真的影响结算（第四节 S3/S4 的 80~84% 复现率暗示有影响），这里的背离就是**结构性的、可重复的**。**这是我最看好的方向。**

**④ 微观结构（口袋是不是假的）**
`[0.95,0.96]` 是否为 stale quote：检查该带内的报价挂单量、更新频率、spread，以及报价落后于 Chainlink 滞后量。
→ 若答案是"报价更新慢"，那这不是定价错误，而是**延迟套利**，只有低延迟才能吃到——那会推翻"拿 2 秒延迟去做市"的可行性。

`+0.402` vs `−0.020` 的对比，**直接证实 RTDS 的 Chainlink 价格是 60s TWAP 类的平滑序列，不是原始现货**。
这与结算规则（"Chainlink BTC/USD 60s TWAP 流"）**完全吻合**。

### 十、更正：水平偏移会被约掉，真正的问题在"平滑滞后"（2026-10-10 19:50）

第九节把 **+9.3bps 的水平偏移**当作主要风险，**这个表述不准确，现更正**：

**偏移会被约掉。** 方向位移 `m = (P_now / P_open − 1)` 里，只要分子分母取自**同一路**价格，恒定的乘性偏移**严格抵消**。
实测验证（11:40 窗口、301 行）：把两路各自除以**自己那路的开盘价**后，
- chainlink 位移区间：0.00 → **+5.23 bps**
- rest（CEX）位移区间：0.00 → **+5.07 bps**
- 两者差的中位 ≈ **+0.03 bps**（偏移完全消失）

所以 **+9.3bps 不是阈值失真的原因**。

**真正不能约掉的是"平滑 + 滞后"。** 证据：

| 指标（1 秒差分） | Chainlink | CEX |
|---|---|---|
| sd（bps） | 0.111 | 0.148 |
| lag-1 自相关 | **+0.402** | **−0.020** |

移动平均会让短于窗口的价格跳动被**摊平**，并让整条序列**滞后约半个窗口（~30 秒）**。
含义是：**同一时刻，CEX 的位移可能已经很大，而 Chainlink（结算变量）还没跟上** ——
所以历史上以 CEX 位移定义的 `mgn≥10`，其中相当一部分对应的真实（Chainlink）位移可能远低于 10bps。
**这正是"用错尺子会产生假信号"的机制**，比水平偏移重要得多。

**因此校准要回答的问题应当改为**：
1. 两路位移的**时序相关性**：`m_chainlink(t)` 与 `m_cex(t+Δ)` 在 Δ≈30s 处是否相关最高（确认滞后量）；
2. 两路位移的**量级比**按"走势型/尖刺型"分组：趋势行情中两者接近，尖刺行情中 Chainlink 显著更小；
3. 关键判定：**`[0.95,0.96] ∧ m_chainlink≥10` 到底存不存在、有多少**（而非用 CEX 阈值去数）。

**顺带修掉的一个数据瑕疵**：`refreshBtcPrice` 原先在 `await` REST 抓取**之后**才回填主列，
导致采样行可能出现 `btc_price` 比 `btc_price_chainlink` 旧一个周期的现象（日志里 `btc=82812.103...` vs `cl=82812.111...`）。
已改为主源在自己那路更新时就**立即赋值**，不再跨 `await`；采集器已重启，`tsc` 0 错误。
