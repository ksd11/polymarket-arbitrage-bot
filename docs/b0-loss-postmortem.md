## 1. 两笔亏损的逐笔解剖

两笔都是「我方持有 UP、结果 DOWN 赢」（live 45 笔里 43 赢 2 亏）。

### 亏损 A — 17:18:24，成交 @0.55（**延迟期崩盘**）

```
17:18:21  up 0.93 / 0.94        ← 正常双边盘，"waiting for probability"
17:18:23  up 0.53 / 0.95        ← 触发！买盘崩到 0.53，卖盘还挂着 0.95（价差 42 分）
17:18:23.546  下单  UP BUY  限价 0.96
17:18:24.242  成交  @0.55，拿到 8.7273 股（延迟 2412ms）
17:18:24  up 0.50 / 0.51        ← 真实市场已在 0.51
17:18:27  up 0.60 / 0.61
17:18:33  up 0.30 / 0.31        ← 再次崩塌，最终结算 0
```

**三重叠加**：① 触发瞬间正好是反转起点；② 2.4 秒延迟里那条腿从 0.94 塌到 0.51；
③ 因为**按美元金额下单**（见 §2），$4.80 在 0.55 的价位买成了 **8.73 股**而不是 5 股。

### 亏损 B — 20:31:56，成交 @0.95（**纯粹 95% 的尾巴**）

进场时 up 0.92/0.93、成交 0.95，之后全程正常，最后 DN 赢。**没有任何前兆**——95% 胜率的策略必然有 5% 的失败，这笔就是那 5%。

### 结论

| | 亏损 A | 亏损 B |
|---|---|---|
| 类型 | 延迟期崩盘成交 | 正常尾部亏损 |
| 事前可辨？ | 理论上要"看到瞬时盘口"，而记录只有 1s 粒度，**无法证实** | **不可辨** |
| cap 0.95 能拦？ | ❌（成交价 0.55 ≤ 0.95） | ❌（成交价 0.95 ≤ 0.95） |

**两笔亏损都不会被任何候选守卫拦住。** 这是本轮最重要的负面结论。

## 2. 【机制】运行器按「美元金额」下单 —— 股数随价格浮动，但美元敞口恒定

> ⚠️ **更正（2026-10-11 10:15）**：本节原先写成"崩盘时自动加仓 / 赌注放大了 75%"，**这是误导**。
> 实盘实测（`限价 0.96 / 成交 0.92 → 5.217387 股 = 4.80 ÷ 0.92`）加 SDK 源码确认：
> **交易所始终按 `makerAmount`（USDC）成交并交割 `makerAmount / fillPrice` 股**。
> 所以**美元敞口恒为 `5 × 限价` ≈ $4.80，与成交价落在哪里无关**；变的只是股数。
> 换言之：便宜成交 = 同样的钱买到更多股（如果它反弹，反而更好），**不是风险放大**。
> 交易所的 `size` 参数只用于按限价反算这笔 USDC。详见 `docs/b0-entry-variants.md` 的开头更正。

`src/btc-5m-latency-scalp.ts:818,857`：

```ts
const notional = normalizedPrice * normalizedSize;      // 0.96 × 5 = $4.80
...
await this.client.createAndPostMarketOrder({ ..., amount: side === "BUY" ? notional : normalizedSize, ... })
```

`createAndPostMarketOrder` 的 `amount` 是**美元金额**。交易所按 `amount / fill_price` 交割股数：

| 成交价 | 股数 | 赢的赔付 | 输的亏损 |
|---|---|---|---|
| 0.96 | 5.0000 | +$0.2000 | −$4.80 |
| 0.95 | 5.0526 | +$0.2526 | −$4.80 |
| 0.89 | 5.3933 | +$0.5933 | −$4.80 |
| **0.55** | **8.7273** | +$3.93（若赢） | **−$4.80** |

**输的时候永远亏掉整个 notional；赢的时候股数越多赚越多。** 所以低成交价在**上行时是加成、下行时不变** —— 这解释了为什么"崩盘成交"那一组在 44.9 天里是净赚钱的（+$34）。

## 3. 被数据否掉的三个"直觉方案"

| **"便宜成交 = 逆向选择，应该规避"** | 44.9 天，成交价 << 触发价的 133 笔 | ❌ **反而是赚钱的**：胜率 **81.2%**，金额制 **+$34.10**（股数制 +$23.29）。崩盘大多是噪声，会弹回来。 |
| **"按股数下单更安全，应改"** | 同样 5,805 笔，两种口径对比 | ❌ **股数制更差**：−$20.36 vs −$8.17（t=−1.55）。因为便宜成交是有溢价的，压小它等于放弃这部分 alpha。 |
| **"价差/买盘守卫能拦住僵尸报价"** | 触发 tick 加守卫 | ❌ **全部无效**：价差 ≤0.02 裁掉 68 笔 → −$11.20（更差）；bid ≥ 0.90 裁掉 16 笔 → −$9.27（更差）。且两笔亏损的触发 tick 价差都只有 **0.01**。 |

## 4. 事前特征扫描：没有失败签名

**单因子分档**（44.9 天，5,805 笔成交，胜率 94.50%）：没有任何一档显著抬高胜率或总盈亏。

**逻辑回归失败预测**（时间切分 60/40，特征 = 触发ask/bid/价差/对腿ask/bps/剩余秒/速度/成交价）：

| 模型 | AUC |
|---|---|
| 仅成交价 | 0.6035 |
| **全部事前特征** | **0.6061** |

加 6 个事前因子只把 AUC 从 0.604 抬到 0.606 —— **等价于没有增量**。

**"筛掉最高风险"的代价-收益曲线**（测试集 n=2,322，失败 130 笔）：

| 筛掉 | 剩余失败 | 裁掉失败 | 剩余总PnL | PnL 变化 |
|---|---|---|---|---|
| 前 2% | 117 | 13 | +21.37 | **+2.45** |
| 前 5% | 113 | 17 | −10.04 | −28.95 |
| 前 10% | 101 | 29 | −3.01 | −21.92 |
| 前 20% | 89 | 41 | −23.49 | −42.40 |
| 前 30% | 73 | 57 | −10.13 | −29.05 |

**只有筛掉 2% 是微正的，之后全部为负。** 说明模型标记的"高风险"里混了大量赢单——这就是 5.5% 失败率下的必然。

## 5. ★ 真正的可控制变量：你付了多少钱

|---|---|---|---|---|---|---|---|

| (0.94,0.95] | 2,130 | 95.40% | 95.32% | +0.08% | +0.0034 | [−0.04,+0.05] | — |

**注意最后一行**：成交在 0.96 时，**赢只赚 +$0.19、输要亏 −$4.81**，打平需要 **96.26%** 胜率，而市场只给 **95.86%**。

> **赔率 25 : 1**（赢 0.19 / 输 4.81）。在 0.96 这个价位，你需要的胜率已经逼近 100%，而那个 0.5 分的点差与 `0.07·p(1−p)` 手续费把胜率甩在后面。

### 5.2 限价上限对比（44.9 天，按每信号 EV）

| 限价上限 | 成交/信号 | 成交率 | 胜率 | 均价 | **总PnL** | **每信号** | 最大回撤 |
|---|---|---|---|---|---|---|---|
| **0.96（现状）** | 5,805/9,121 | 63.6% | **94.50%** | 0.9420 | **−$8.17** | −0.90m$ | $121.56 |

**关键反直觉点**：cap 0.95 的**胜率更低**（94.14% vs 94.50%），但总盈亏从 −$8 变成 **+$46**。
它改变的不是"失败频率"，而是**赔付比**：均价从 0.9420 降到 0.9337，每次赢多赚一点，而每次输仍然只亏 $4.75。


## 6. 落地建议

**唯一建议的改动**：把上限从 0.96 降到 0.95。

```bash
# scripts/strat-b0.sh 里加/改：
MAXP=0.95 BUF=0.00            # 限价 = min(ask+0.00, 0.95) ⇒ 只在 0.95 成交
```

或直接设 env：
```
FINAL_30_MANAGED_MAX_ENTRY_PRICE=0.95
FINAL_30_MANAGED_TAKER_BUY_MAX_PRICE=0.95
FINAL_30_MANAGED_TAKER_BUY_BUFFER=0
```

**取舍**：成交率从 63.6% 降到 **50.9%**（每晚约 45 笔 → 36 笔），换来"永不付 0.96"。

### ⚠️ 必须知道的边界

1. **统计不显著。** bootstrap 95%CI 含 0；每个成交价档的 CI 也全部含 0。这是**方向性证据**，不是已证实结论。44.9 天里 $54 的差别，被 ~319 次 −$4.8 的二元亏损噪声完全淹没。
2. **实盘样本与模型不一致。** 模型里 0.96 成交占 **31.6%**，而昨夜实盘只有 **15%**（6/40）。若真实比例更低，cap 0.95 的收益会同比例缩小。
3. **昨夜实盘如果用了 cap 0.95 会更差**：那 6 笔 0.96 成交全赢（+$1.20），剔掉后 5h21m 的成绩从 +$1.71 变成 +$0.51。**单夜是噪声，不要用它验证。**
4. **成交率模型假设"顶档 ask 有无限深度"**，而实盘出现过 `taker_no_match`（顶档报价太薄）。cap 0.95 时成交率可能低于模型值——建议先跑 **dry-run 数小时**，实测成交价分布再上真单。
5. **两笔实盘亏损都不会被这条改动拦住**（一笔 0.55、一笔 0.95）。它改善的是**赔付比**，不是"抓失败"。
