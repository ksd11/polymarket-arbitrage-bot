## 四、技术故障根因

### 1. 218 次下单被拒（HTTP 400）—— 最高优先级

日志证据（23:54:42 那一帧）：

```
23:54:41.891  Down Ask: 0.8400
23:54:42.292  Entry decision: final-30-high entry ask=0.85 ...
23:54:42.880  ERROR Failed to post entry BUY DOWN @ 0.850000: 400
23:54:42.897  Down Ask: 0.8500
```

**根因**：`buildBtc5mFinal30HighOrders` 用 WebSocket 快照的 `ask` 作为下单价，`placeOrder` 用 `OrderType.GTC`（maker 限价单）挂在 `ask` 价。final 30s 盘口每秒跳 0.01~0.02，等请求到 CLOB 时，那个价位的卖单已被抢走或变成自成交，CLOB 返回 400。

- 下单失败（218 次）比成功挂单（175 次）还多
- 每次失败还会 `state.cancelled = true`，导致本轮市场彻底放弃

**修复方向**：改用吃单（taker，`OrderType.FOK/IOC`），或下单前用最新 bid/ask 重新取价，或降低触发价（0.85 → 0.80 以下）。

### 2. 734 次 WebSocket 断线

`WebSocket closed: 1006`（异常断开）+ `1013 slow consumer: send buffer full`（本地消费跟不上）。final-30 依赖毫秒级时序，断线期间基本瞎打。

### 3. 止损形同虚设

配置 `takeProfitDelta=0`（止盈关闭）、`stopLossDelta=0.1`。止损价 = 入场价 - 0.1，挂在 0.75~0.80 这种价，在 final 30s 根本等不到成交，等于没有止损。16 笔中途退出的单，退出价都在 0.03~0.49 的极端位置。

## 五、结论与建议（按优先级）

| 优先级 | 问题 | 建议 |
|--------|------|------|
| 🔴 P0 | 400 拒单 | 改吃单（FOK/IOC）或下单前重新取价；降触发价 |
| 🔴 P0 | 盈亏比结构 | 入场价压到 ≤0.80，或缩小仓位让单笔亏损 ≤ 盈利 2 倍 |
| 🟡 P1 | 止损失效 | 改 BTC 反向幅度硬止损，别挂低价 maker 单 |
| 🟡 P1 | 余额熔断 | 余额 < $4.5 时 stop 进程，别空转 |
| 🟢 P2 | WebSocket 抖动 | 断线重连加退避 + 断线期间禁止下单 |

**总评：`final-30-managed` 当前参数实盘亏损 -$38（回撤 104%），方向判断不差（79.6% 胜率），但被「高价 maker 入场 + 无有效止损」的双重结构缺陷锁死。** 与回测数据里「66% 胜率、薄利」的预期严重背离，主要原因是回测没有计入 maker 单成交率和滑点。
