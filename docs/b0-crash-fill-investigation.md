# 「挂单 0.95、成交 0.55」能不能事前避开？

> 问题来源：用户认为"挂 0.95 却以 0.55 成交"是明显的反转信号，应当可以避免。
> 数据：44.9 天 / 12,024 窗口 / 1,039,610 行；实盘 `data/live-b0-20261011-002255.csv`
> 复现：`python3 scripts/b0_dislocation_guard.py 2`

---

## 结论

**机制上无法在成交时避免；事前检查也抓不到**——133 笔"击穿成交"里 **132 笔（99.2%）的触发 tick 盘口完全健康**（价差中位 **0.010**、对腿卖价中位 **0.060**、我方 bid 中位 **0.940**），与正常组一模一样。

**唯一能事前看见的那一类（盘口错位）在数据里是 17 例、16 胜、净 +$1.39。** 也就是说：**按这个信号去过滤，你过滤掉的主要是赢单。**

真正的机制是：**成交价本身就是结局，不是你可以据以行动的观测量。**

---

## 1. 先把机制讲清楚：FAK 不可能"看到 0.55 再决定"

| 事实 | 说明 |
|---|---|
| 限价是**上限**，不是目标价 | 你挂 0.96，交易所按**当时最优卖价**成交。最优卖价 0.55 时就按 0.55 成交（对你有利的价格改善），你无法拒绝。 |
| FAK 是**原子**操作 | 撤单指令到达时订单已经成交。没有"预览—确认"这一步。 |
| 因此 | 任何"避免"都只能发生在**发送之前**，用**盘口快照**判断这个 0.95 的卖单是否有买盘支撑。 |

## 2. 实盘那一笔的真实时间线（关键）

```
17:18:19.094  decision  up 0.93/0.94      ← 正常双边盘（价差 0.01）
17:18:20.106  decision  up 0.93/0.94
17:18:21.118  decision  up 0.93/0.94      ← 最后一次被记录的正常快照
              ⋮  2.4 秒空白（决策记录被 recordIntervalMs=1000 节流，
                 且下单路径阻塞了决策循环）
17:18:23.546  order_posted                 ← 下单
17:18:23.647  decision  up 0.53/0.95       ← 错位盘口出现在【下单之后 0.1s】
17:18:24.242  order_trade_fill @0.55       ← 成交（8.7273 股）
17:18:24.657  decision  up 0.50/0.51       ← 完整崩塌
```

**下单所依据的那个快照，记录里不存在。** 触发必须发生在 ask ≥0.95 的某一帧；最后一帧 ask<0.95 是 21.118（0.93/0.94），所以触发帧落在 21.1–23.5 之间，无法证实其盘口状态。
从 23.647 这一帧（ask 恰为 0.95，bid 0.53）推断，触发帧**很可能**也是这个错位状态，但**未被记录**。

## 3. 大规模检验：错位是不是"击穿"的签名？

**判定**：击穿成交 = 成交价相对触发 ask 下移 >10 分（`drift < −0.10`）。
44.9 天里共 **133 笔**（占 5,805 笔可成交的 2.3%）。

### 3.1 击穿组的触发盘口 vs 正常组 —— 一模一样

| 触发 tick 特征 | 击穿组（n=133） | 贴合成交组（n=2,483） |
|---|---|---|
| 我方腿价差 中位 / p90 | **0.010 / 0.010** | 0.010 / 0.010 |
| 对腿卖价 中位 / p90 | **0.060 / 0.060** | 0.060 / 0.060 |
| 我方腿 bid 中位 / p90 | **0.940 / 0.950** | 0.940 / 0.950 |

**击穿组的触发盘口完全健康。** 击穿不是"下单前可见的错位"，而是**下单后 1–2 秒内市场突然重定价**。

### 3.2 击穿成交的触发价差分布

| | 值 |
|---|---|
| 中位 / 均值 | **0.010 / 0.011** |
| p95 / 最大 | 0.010 / 0.100 |
| **价差 > 0.05 的** | **1 笔 / 133（0.8%）** |
| **对腿卖价 > 0.12 的** | **1 笔 / 133（0.8%）** |

### 3.3 各类守卫的实际效果（44.9 天）

基线：成交 5,805 笔、胜率 94.50%、总 PnL **−$8.17**、其中击穿 133 笔。

| 守卫 | 保留 n | **拦住的击穿** | 胜率 | 总PnL | vs 基线 |
|---|---|---|---|---|---|
| 我方腿价差 ≤ 0.02 | 5,737 | **4** | 94.51% | −$11.20 | −$3.04 |
| 我方腿价差 ≤ 0.05 | 5,788 | **1** | 94.51% | −$9.56 | −$1.39 |
| 我方腿价差 ≤ 0.10 | 5,803 | **0** | 94.50% | −$8.69 | −$0.52 |
| 对腿卖价 ≤ 0.06 | 5,662 | **5** | 94.51% | −$12.30 | −$4.13 |

**所有守卫都拦不住 97% 以上的击穿，而且每一个都让 EV 变差。**

## 4. 为什么"事后看很明显"是错觉

成交价 0.55 **本身就是那个反转**——它是**结果**，不是发生在结果之前、可以据以决策的**观测量**。

把结果当成信号，等价于用未来信息。真正的问题是：
> 在**发送订单那一刻**，0.95 的卖单和 0.55 的卖单看起来完全一样。

这正是"幸存者偏差的反面"——**你只在那 2.3% 的击穿里看到了 0.55，却看不到另外 97.7% 里那 0.95 的卖单同样"可疑"**，而它们没有任何损害。

## 5. 有没有任何状态能"抬高击穿率"？有——但那些状态最赚钱

换了几个因子后确实找到了能显著改变**击穿率**的状态（44.9 天，基线击穿率 2.29%）：

| 触发时状态 | n | **击穿率** | 倍数 | 胜率 | 总PnL |
|---|---|---|---|---|---|
| `vel_leg < 0`（合约价正在跌） | 1,124 | **5.16%** | **×2.25** | 93.59% | −$6.76 |
| `vel_leg ≥ 0`（正在涨，实盘那笔如此） | 4,679 | 1.60% | ×0.70 | 94.72% | −$1.78 |
| `acc_leg < 0` | 2,383 | 3.23% | ×1.41 | 94.75% | **+$70.76** |
| `vel<0 且 \|margin\|<1bps` | 187 | **8.02%** | **×3.50** | 93.05% | −$0.13 |
| `margin < 0`（BTC 逆着我方走） | 109 | **10.09%** | **×4.40** | **97.25%** | **+$25.31** |
| **`vel>0 且 \|margin\|<1bps`（★实盘那笔的状态）** | **282** | 2.48% | ×1.08 | **97.16%** | **+$42.46** |

**这张表是本轮最重要的发现**：

- **击穿率是可以被改变的**（最高 ×4.40）。所以"能不能识别易击穿状态"——**能**。
- **但击穿率与盈亏反相关**：击穿率最高的两个状态（`margin<0` ×4.40、`vel<0 且 |margin|<1` ×3.50）里，前者胜率 **97.25%、净 +$25**，后者基本上不亏。
- **实盘那一笔所在的状态（`vel>0` 且 `|margin|<1bps`，n=282）击穿率几乎是全样本平均（×1.08），但胜率 97.16%、合计 +$42.46 —— 这是最赚钱的桶。**
- `acc_leg < 0` 击穿率 ×1.41，却是全样本里最赚的（+$70.76）。

> 也就是说：**"击穿"本身不是亏损的来源。** 击穿时你买得更便宜，而便宜买入在 44.9 天里是净赚的。
> 想靠"避开易击穿状态"来提高收益，方向从一开始就错了。

## 6. 那还能做什么（按有效性排序）

| 手段 | 效果 | 状态 |
|---|---|---|
| **① 按股数下单** | 崩盘成交时亏 `5 × 成交价`（$2.75）而不是固定 $4.80。实盘那笔省 **$2.05** | ✅ **已实现**（`takerBuyByShares`） |
| **② 限价上限 0.95** | 从结构上不付 0.96 那一档（该档在 44.9 天里贡献 −$37） | ✅ 已给方案（`MAXP=0.95`） |
| **③ 价差闸门 `TREND_MAX_SPREAD`** | **拦不住 97% 的击穿**，只拦 1–5 笔；EV 略降（−$1.4 ~ −$4.1） | ⚙️ **已存在**（默认 0.03，B0 里被设成 0.99 关掉了）。可以开，属**免费保险**，不是解法 |
| **④ 降低延迟** | 触发→上报有 2.4 秒空窗；窗口越短，盘口错位的暴露期越短 | 🔧 未做（预签名订单可把它压到 1 次 HTTP） |

### 建议

1. **主防线是仓位**（①，已做）：看不见的东西只能靠"亏小一点"来管。
2. **③ 可以顺手开**：它极难触发（0.3–1.2%），所以成本接近 0；它确实能挡住"看得见的那一类"。但**不要把它当成"避免击穿"的办法**——它只能挡 1/133。
3. 若要真正缩短暴露期，唯一的方向是 **④ 降低下单延迟**（预签名 + 复用连接）。

### 开启价差闸门的方式

```bash
# scripts/strat-b0.sh 的 CFG 数组里把这一行改掉：
FINAL_30_MANAGED_TREND_MAX_SPREAD=0.03     # 现值 0.99（关闭）
```

语义（`src/strategies/btc5m/final-30-managed.ts:182`）：
```ts
const spread = quote.price - bid;           // 我方腿 ask − bid
if (input.params.trendMaxSpread > 0 && spread > input.params.trendMaxSpread) { ... 放弃本腿 ... }
```

## 7. 一句话

**击穿不是"看得到的反转"，是"看不到的重定价"。**
事前可见的错位（17 例）里 16 例是赢的；133 例击穿里 132 例的触发盘口干净得像教科书；
而**能抬高击穿率的状态恰恰是最赚钱的状态**（`margin<0` 击穿率 ×4.40 / 胜率 97.25% / +$25）。
能做的只有把损失做小（按股数下单，已实现），不是把它预测掉。
